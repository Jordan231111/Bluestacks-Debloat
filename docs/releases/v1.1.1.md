# BlueStacks Debloat 1.1.1

Android package, animation and root-network operations now recover from transient ADB connection resets. Exact package/settings writes retry only transport failures, check the selected instance before every attempt, and verify the final value. Permission errors and confirmed Android failures remain visible instead of being retried.

The UI refreshes running-instance status after operations and selects an appropriate fallback when a saved instance no longer exists. The Root tab clearly labels its size figure as an **estimate for a new backup**; saved recovery points are managed separately in Backups & restore. Debloat & tune now points to the Network option for the home screen's **Popular games to play** tiles. Launcher isolation requires Magisk and also blocks the launcher's online search and Store connections.

Validated on **BlueStacks 5.22.288.1014, Android 13**:

- Maximum, Android apps, fresh Magisk installation, Android hosts filtering and launcher isolation applied and verified.
- Two complete player restarts retained all settings, disabled packages, Magisk, the hosts overlay and IPv4/IPv6 launcher rules. Every repeated review reported no pending changes.
- The bottom-row ad tiles disappeared; the empty heading/background remained. Settings, Google Play's sign-in screen and Chrome's first-run screen opened successfully. No account sign-in, app download or game compatibility test was performed.
- CPU/RAM remained at 4 cores / 8 GiB; the FPS limit is 240. BlueStacks X / Services were already absent and their review found no leftovers to change.
- Formatting, Clippy with warnings denied, 103 automated tests (including 840 UI layouts), and the optimized Windows x64 build passed.
- Live fault injection during package writes, animation writes and root-network checks recovered successfully. The Rust dependency audit reported no known vulnerabilities or warnings.
